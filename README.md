# Pachinko

A browser pachinko game in TypeScript. Three themed machines (Raijin, Big Wave,
Hana Fan), each with its own layout, tuning and cel art. Land the start chucker
to queue a reach: three reels spin and, on a match, the attacker opens for a
jackpot. Bank and best scores persist per machine.

The core (RNG, physics, game state) is pure TypeScript with no DOM dependency.
A canvas renderer, a DOM panel, a dial input and a storage adapter sit on top.

## Quick start

```bash
npm install
npm run dev        # Vite dev server for the standalone page
```

## Delivery targets

- **Single file:** `npm run build:standalone` writes `dist/pachinko.html` with
  everything inlined; it opens from a file URL.
- **Next.js:** `npm run dev -w web`, then open `/play`. The route mounts the
  game in a client component with server rendering disabled and passes the
  storage adapter as a prop (`LocalStorage` by default). A custom `storage`
  adapter is passed to `PachinkoClient` from a client component and should be
  memoized: a new instance per render re-creates the `App`.

Both targets import the package through `src/index.ts`, which exports `App`,
the machine table, the `Storage` types and the `LocalStorage` / `MemoryStorage`
adapters.

## URL parameters

- `?m=raijin|big-wave|hana-fan` picks the machine.
- `?seed=<integer>` fixes the RNG seed. The debug overlay's copy link
  produces a URL with both.

## Keyboard

| Key | Action |
| --- | --- |
| Space (hold) | Charge the launcher; release to fire. Holding past 1.2 s auto-fires. |
| Up / Down arrows | Trim strength (any time; the value resets at the next hold) |
| 1 / 2 / 3 | Switch machine |
| M | Mute |
| ` (backtick) | Toggle the debug overlay (fps, balls, phase, seed) |

## Scripts

| Script | What it does |
| --- | --- |
| `npm test` | Vitest unit and simulation tests |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run e2e` | Playwright smoke tests against the Vite dev server (port 5199) |
| `npm run balance` | Headless soak; prints return rate per machine and launch strength |
| `npm run cels` | Embeds `assets/cels/*.svg` into `src/render/cels/*.ts` |

The cel SVGs are generated by `docs/superpowers/specs/cels/gen_cels.py` and
copied into `assets/cels/`. After editing an SVG in `assets/cels`, rerun
`npm run cels`; the embedded TypeScript is not regenerated automatically.

## Layout

```
src/core/       RNG, physics, layouts, machines, game state (no DOM)
src/render/     canvas renderer, themes, embedded cels
src/panel/      DOM panel, overlays
src/input/      dial (pointer + keyboard)
src/audio/      synthesized sounds
src/storage/    Storage interface, LocalStorage, MemoryStorage
src/app.ts      App: wires core, render, panel, input, audio, storage
src/index.ts    package entry
standalone/     Vite single-file target
apps/web/       Next.js app with /play
tests/          Vitest
e2e/            Playwright
tools/          balance soak, cel embedder
assets/cels/    machine cel SVGs
docs/           spec, plan, screenshots
```

## Notes

`postbuild:standalone` renames the output with `mv`, so the standalone build
assumes a Mac or Linux shell.
